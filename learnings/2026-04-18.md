# Learning Points from Timeline

## AI / Machine Learning

- **Prompt engineering for Claude Opus 4.7**: Opus 4.7 requires a different interaction style than 4.6 — the way you prompt matters for getting good results, and Anthropic shipped tips for dogfooding effective workflows. _Source: @bcherny ([post](https://x.com/bcherny/status/2044847848035156457)), @DimitrisPapail ([post](https://x.com/DimitrisPapail/status/2045314303604224205))_

- **Adaptive Thinking mechanics**: Opus 4.7's "Adaptive Thinking" lets the model decide when to reason, and on average it uses *more* thinking tokens than 4.6 — not fewer. Rate limits were raised to compensate. The model picks when deep reasoning helps rather than always-on thinking. _Source: @bcherny ([post](https://x.com/bcherny/status/2044836750066151666))_

- **Non-canonical tokenization affects inference**: "Broken Tokens" (Zheng et al. 2025) showed that non-canonical tokenizations at inference time can improve instruction following — a possible mechanistic explanation for Claude Opus 4.7's 1.0–1.35× increased token usage. _Source: @iamgrigorev ([post](https://x.com/iamgrigorev/status/2045044753230598307))_

- **Tokenization and counting tasks**: Asking an LLM "how many P's in strawberry" is really asking "how many [151]'s in [15563][23][4124]" — the model sees subword tokens, not letters, which explains persistent failures on character-counting questions. _Source: @kettukaa ([post](https://x.com/kettukaa/status/2045011064417644665))_

- **Ternary-weight LLMs (Ternary Bonsai)**: Using weights from {-1, 0, +1} (1.58 bits), Prism ML built models 9× smaller than 16-bit counterparts while outperforming most models in their parameter classes on standard benchmarks — evidence that extreme low-bit quantization can retain capability. _Source: @PrismML ([post](https://x.com/PrismML/status/2044833023682896134)), @HessianFree ([post](https://x.com/HessianFree/status/2044833071979987426))_

- **Looped transformers as RNNs**: A dynamical-systems view of looped transformers yields clean stability conditions; it also makes clear that looped transformers are effectively recurrent networks, providing a bridge between transformer and RNN analysis. _Source: @tri_dao ([post](https://x.com/tri_dao/status/2044842948118921703)), @AntonObukhov1 ([post](https://x.com/AntonObukhov1/status/2045065565128044791))_

- **Looped architectures scale differently (Parcae)**: Layer looping with the right parameterization gives a new axis to scale FLOPs — matching Transformers 2× their size with the same data. An SSM-on-residual-stream dynamical-systems view informs the right way to scale looped nets. _Source: @tri_dao ([post](https://x.com/tri_dao/status/2044843114934751390)), @realDanFu ([post](https://x.com/realDanFu/status/2044914117363094012))_

- **Muon optimizer as implicit Newton method**: The Muon optimizer is secretly an implicit Newton method; leveraging this insight produces the "Newton–Muon" optimizer, a principled improvement derived from second-order structure. _Source: @weijie444 ([post](https://x.com/weijie444/status/2044827795151376548))_

- **MoE load balancing via quantile balancing**: Marin is training with "quantile balancing" from Jianlin Su (also the inventor of RoPE) — an elegant open method for balancing experts in MoE models, developed through open experimentation and blog posts. _Source: @Yulun_Du ([post](https://x.com/Yulun_Du/status/2045046201247207426)), @Tim_Dettmers ([post](https://x.com/Tim_Dettmers/status/2045076584713904212))_

- **SFT warm-up from RL environments**: If you have an RL environment, you already have an SFT data factory — run a strong model through the env, filter rollouts by reward, and use the result for SFT warm-up before RL (RL needs signal to amplify; SFT provides format/basics). _Source: @theanakin87 ([post](https://x.com/theanakin87/status/2045149977790263335))_

- **SFT data correctness debate**: Large open-weights labs (DeepSeek, Zhipu) filter SFT data for correctness, but smaller labs like OpenThoughts report that including incorrect responses in SFT can also help — an unresolved question of when noisy traces regularize vs. corrupt policy formation. _Source: @finbarrtimbers ([post](https://x.com/finbarrtimbers/status/2044837263407014376)), @novasarc01 ([post](https://x.com/novasarc01/status/2044852946865934815))_

- **Dense supervision from sparse rewards (SD-Zero)**: A new method uses a model's self-revision to turn RLVR binary rewards into dense token-level supervision — no external teacher or high-quality demonstrations required. Bridges RLVR and on-policy self-distillation. _Source: @danqi_chen ([post](https://x.com/danqi_chen/status/2045136466343305342)), @prfsanjeevarora ([post](https://x.com/prfsanjeevarora/status/2045226767514828961))_

- **LoRA rank and training dynamics**: LoRA adapters of varying ranks trained on GSM8k live in a surprisingly vast, low-rank solution space, suggesting some model skills are easy to learn and training is more forgiving than expected. _Source: @jackson_stokes ([post](https://x.com/jackson_stokes/status/2045213382282817757))_

- **Sim2Reason — physics from simulation**: Training LLMs inside virtual worlds governed by real physics laws (zero human annotation) produced +5–10% on International Physics Olympiad zero-shot — learning physics through simulated experience rather than text. _Source: @mihirp98 ([post](https://x.com/mihirp98/status/2044830431850250400))_

- **Emergent compositional generalization in robotics (π0.7)**: Physical Intelligence's π0.7 can fold shirts it has no training data for, operate appliances via language coaching (e.g., using an air fryer to cook a sweet potato), and transfer to new embodiments (folding t-shirts on a UR5e with no laundry training data on that robot) — emergent transfer in VLA-style robotic policies. _Source: @physical_int ([post](https://x.com/physical_int/status/2044841263254638862)), @physical_int ([post](https://x.com/physical_int/status/2044841443299381314)), @physical_int ([post](https://x.com/physical_int/status/2044842117839864256))_

- **World models need 3D (PointWorld)**: Wenlong Huang argues 3D is the missing side of the coin for robotics scaling — more than a better policy backbone. _Source: @drfeifei ([post](https://x.com/drfeifei/status/2044982539467764112))_

- **Perplexity probe vector in Gemma 4**: A single direction in Gemma 4 e4b fires more strongly on higher-surprisal passages (R²=0.775, correlation 0.880), with L20/L21 alone reaching R² ~0.83 — evidence that models maintain an internal "surprise" signal accessible via linear probes. _Source: @_lyraaaa_ ([post](https://x.com/_lyraaaa_/status/2045373503311122712))_

- **Perplexity is questionable for post-trained models**: Due to entropy shaping during RL, a base model's perplexity can exceed a post-trained model's while the post-trained model is more useful — a caution for using perplexity as a utility proxy. _Source: @eliebakouch ([post](https://x.com/eliebakouch/status/2045106416952733964))_

- **Late-interaction retrieval beyond retrieval**: ColBERT-style late-interaction representations can effectively replace raw document text inside RAG pipelines, not just serve retrieval. _Source: @lateinteraction ([post](https://x.com/lateinteraction/status/2045218109510889496))_

- **Chess transformer interpretability**: BT4 (Leela Chess Zero's strongest open-source model) reaches grandmaster play in a single forward pass; Transcoders and Lorsas show sparse replacement layers can reproduce this — opening mechanistic-interpretability inroads into strategic play. _Source: @Xidong_Feng ([post](https://x.com/Xidong_Feng/status/2044900414680666587))_

- **Platonic Representation Hypothesis is fragile**: New work ("Back into Plato's Cave") argues the evidence that vision and language models converge to the same representation of reality is weaker than the Platonic Representation Hypothesis claims. _Source: @berkeley_ai ([post](https://x.com/berkeley_ai/status/2045512027419115669))_

- **Empowerment ↔ causal models**: A theoretical link between the "empowerment" objective in RL and Bayesian causal models, with new experimental data. _Source: @berkeley_ai ([post](https://x.com/berkeley_ai/status/2045509877372711349))_

- **Insight anticipation is hard**: Given two "parent" papers, can LMs generate the core insight of a future paper built on them? Frontier models aren't improving at this synthesis task; RL helps somewhat. _Source: @stanfordnlp ([post](https://x.com/stanfordnlp/status/2045192119086887291)), @stanfordnlp ([post](https://x.com/stanfordnlp/status/2045150796741046591)), @stanfordnlp ([post](https://x.com/stanfordnlp/status/2045192240465936684))_

- **Open-world evaluations replacing benchmarks**: As benchmarks saturate faster than ever, the frontier-eval community is converging on "open-world evaluations" — long, messy, real-world tasks impractical for classic benchmarks. _Source: @sarahookr ([post](https://x.com/sarahookr/status/2044875768833159324))_

- **Benchmark auditing (BenchJack)**: UC Berkeley's BenchJack "pen-tests" agent eval benchmarks to surface reward hacks and shortcuts — broke 8 major agent benchmarks; open-sourced. _Source: @berkeley_ai ([post](https://x.com/berkeley_ai/status/2045510970009874593)), @berkeley_ai ([post](https://x.com/berkeley_ai/status/2045510937051107610))_

- **FrontierSWE benchmark**: 11-hour average runtime, open-ended tasks like end-to-end model optimization — frontier agents fail nearly all of them, showing the gap to ultra-long-horizon coding. _Source: @novasarc01 ([post](https://x.com/novasarc01/status/2044881177996365857)), @eliebakouch ([post](https://x.com/eliebakouch/status/2044924298586923121))_

- **Modern ML systems as selective reconstruction**: Much of modern ML systems work is about replacing fully materialized computation with selectively reconstructed computation — finding the minimal representation of state/computation sufficient for the task. Async RL is the same idea: absorb compressed/stale info while preserving policy-relevant signal. _Source: @novasarc01 ([post](https://x.com/novasarc01/status/2045225653218226404)), @novasarc01 ([post](https://x.com/novasarc01/status/2045228959659688341))_

- **Vision model limits**: Frontier models still fail basic perception tasks — e.g., identifying a C-major chord from an image; Gemini 3.1 Pro got it, GPT-5.4 and Opus 4.7 did not. ## Software Engineering

- **Claude Code stale-prompt bug**: "This might be malware" refusals on normal code edits in Opus 4.7 were caused by an older build applying a stale safety prompt — fixed by `claude update` or relaunch. - **LLMs for large codebase maintenance**: The belief that LLMs help only with greenfield code but not with maintaining large existing codebases no longer holds — recent agent capability has closed that gap. _Source: @simonw ([post](https://x.com/simonw/status/2045204429281067161))_

- **From-scratch GPT-2 in C++20**: A ~6M-param GPT-2 was trained entirely in pure C++20 with no PyTorch or external deps, and generates mostly-grammatical English — proof that small model training is tractable without the standard DL stack. _Source: @VishnuSatish_ ([post](https://x.com/VishnuSatish_/status/2045531254498480351))_

- **Local-first retrieval in Rust (Witchcraft)**: Dropbox open-sourced Witchcraft, a local search engine in Rust using ColBERT/late-interaction-style retrieval — no API keys, no vector DB — packaged for use by coding agents. _Source: @lateinteraction ([post](https://x.com/lateinteraction/status/2044867541541978518))_

- **DSPy/GEPA accelerate model evaluation**: Dropbox's team can evaluate whether a newly released model is worth switching to in ~1 day using DSPy + GEPA harnesses — an example of prompt/program-optimization frameworks acting as model-swap insurance. _Source: @lateinteraction ([post](https://x.com/lateinteraction/status/2044837403324498375))_

- **Craftax.c — RL envs on CPU**: A pure C / AVX-512 port of Craftax outperforms CUDA versions, underscoring that for many RL workloads GPUs are not "CPUs but faster" — vectorized CPU can win when control flow dominates. _Source: @jsuarez ([post](https://x.com/jsuarez/status/2045515666208244016))_

- **Passkey adoption as a security signal**: Passkey support is a positive trust indicator — they have quietly displaced fragile 2FA codes and made many sites meaningfully more secure over the past 2–3 years. _Source: @sriramk ([post](https://x.com/sriramk/status/2045434795329458201))_

## Security

- **V8 BigInt sandbox bypass**: A memory-corruption bug during BigInt division in V8 leads to a sandbox bypass (Project Zero) — reinforces that even narrow arithmetic paths in widely-deployed JITs are high-value attack surface. _Source: @alkalinesec ([post](https://x.com/alkalinesec/status/2045370789654921269))_

- **HTTP request-smuggling on Discord**: A detailed write-up on using HTTP desync (request smuggling) to spy on Discord attachments — a reminder that HTTP/1.1 smuggling is still a live exploit class at major services. _Source: @giffmana ([post](https://x.com/giffmana/status/2045501937718624621))_

- **Markdown prompt injection is a serious attack surface**: Agents reading markdown (docs, READMEs, web content) can be hijacked via embedded instructions — for some devs this is now a bigger fear than arbitrary executables. _Source: @lucasmeijer ([post](https://x.com/lucasmeijer/status/2045489546825986372))_

- **Agent Identity SDK (World + Okta + Vercel + Zoom)**: A new SDK lets you delegate identity to an agent "power-of-attorney"-style — an early answer to the access-control problem that arises when autonomous agents act on users' behalf. _Source: @benhylak ([post](https://x.com/benhylak/status/2045203357061820532))_

- **Open-source security in an agent era**: Argument that open source will be multiple times more secure than closed-source in the agentic-coding era — because validation (finding vuln signal) is getting cheap; the moat is moving from model access to trusted security validation. _Source: @ClementDelangue ([post](https://x.com/ClementDelangue/status/2044946822611791875)), @stanfordnlp ([post](https://x.com/stanfordnlp/status/2045193032165916755))_

## Key Takeaways

1. **Low-bit and MoE architectures are moving frontier capability to consumer hardware** — ternary (1.58-bit) models rival FP16 peers, and 2-bit Qwen3.6-35B-A3B runs on a 4090 with 13GB RAM at ~180 tok/s while being usable for real agentic coding. The inference-cost frontier is shifting fast. _Source: @PrismML ([post](https://x.com/PrismML/status/2044833023682896134)), @ClementDelangue ([post](https://x.com/ClementDelangue/status/2044972674468728863))_

2. **Cross-datacenter P/D disaggregation with heterogeneous hardware is now practical** thanks to hybrid attention architectures — compute fungibility is becoming real, which changes inference economics and hardware procurement strategy. _Source: @AnjneyMidha ([post](https://x.com/AnjneyMidha/status/2045521691011649537)), @james0zan ([post](https://x.com/james0zan/status/2045466024162836630))_

3. **Benchmarks are saturating and being audited** — the community is converging on open-world evaluations, while tools like BenchJack show existing agent benchmarks can be gamed and need to be pen-tested before you trust them. _Source: @sarahookr ([post](https://x.com/sarahookr/status/2044875768833159324)), @berkeley_ai ([post](https://x.com/berkeley_ai/status/2045510970009874593))_

4. **Cost-per-token is the right AI infra metric in a power-constrained world** — not cost/GPU-hour or FLOPs/dollar — because demand for intelligence is scaling faster than power/infra can keep up. _Source: @nvidia ([post](https://x.com/nvidia/status/2045246300724113652))_

5. **Markdown prompt injection is now a more realistic threat than arbitrary executables** — any agent reading untrusted docs/web/README content is an attack surface; treat agent context windows as privileged execution environments. Combined with the new Agent Identity SDKs, access control for autonomous agents is a distinct security domain. _Source: @lucasmeijer ([post](https://x.com/lucasmeijer/status/2045489546825986372)), @benhylak ([post](https://x.com/benhylak/status/2045203357061820532))_
