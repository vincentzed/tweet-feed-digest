# Learnings - 2026-06-05 02:50

## AI / Machine Learning

- **Recursive self-improvement is now measurable**: Anthropic reports internal data showing Claude is accelerating its own development—each model release is tested by giving it code that trains a small AI model and asking it to speed it up, a concrete benchmark for AI-building-AI capability. _Source: @AnthropicAI ([post](https://x.com/AnthropicAI/status/2062568862479208923))_
- **AI authorship of production code**: As of May 2026, Anthropic says >80% of code merged into its codebase was authored by Claude, and engineers ship ~8x as much code per quarter as in 2021–2025—useful real-world data points on AI coding leverage (though "lines of code" and "authored vs. reviewed" are contested as productivity metrics). _Source: @scaling01 ([post](https://x.com/scaling01/status/2062570523012341985)), @charliermarsh ([post](https://x.com/charliermarsh/status/2062608530620682590))_
- **Nemotron 3 Ultra architecture**: NVIDIA's flagship open-weight reasoning model is a 550B-parameter (55B-active) Hybrid Mamba-2/Transformer MoE with a LatentMoE design, 1M-token context, Multi-Token Prediction, and multi-environment RL—engineered for long-horizon agentic workloads (plan/code/test/debug across large working sets), delivering ~5x faster inference and up to 30% lower cost on agentic tasks, served in NVFP4 (esp. optimized for Blackwell). The full recipe is open: base, post-trained, reward checkpoints, and NVFP4 quantized weights. _Source: @NVIDIAAI ([post](https://x.com/NVIDIAAI/status/2062521325076299981)), @NVIDIAAI/@rasbt ([post](https://x.com/NVIDIAAI/status/2062577349514899656)), @charles_irl ([post](https://x.com/charles_irl/status/2062520838994416037)), @ClementDelangue ([post](https://x.com/ClementDelangue/status/2062544764038152634)), @bernhardsson ([post](https://x.com/bernhardsson/status/2062657918898446474)), @togethercompute ([post](https://x.com/togethercompute/status/2062520012561096709))_
- **Nemotron post-training pipeline**: The RL recipe combines PivotRL, a Generative Reward Model, Multi-teacher On-Policy Distillation (MOPD/OPD), and MTP boosting, built on Nemo RL + Nemo Gym. MOPD is a serious post-training choice in settings where pure RLVR is too sparse and unstable—an emerging alternative to reward-only fine-tuning. _Source: @BanghuaZ ([post](https://x.com/BanghuaZ/status/2062584993185165715)), @novasarc01 ([post](https://x.com/novasarc01/status/2062547168100282801))_
- **Encoder-free multimodal models**: Gemma 4 12B is a unified multimodal model where text, image, audio, and video all project directly into the LLM's embedding space—no separate vision or audio "towers"—with 256K context, Apache 2.0 license, and small enough to run locally on a 16GB-VRAM laptop. _Source: @demishassabis ([post](https://x.com/demishassabis/status/2062241713398149524)), @vllm_project ([post](https://x.com/vllm_project/status/2062228047324201166))_
- **Qwen3.7-Plus**: Alibaba's new model is a unified multimodal agent that integrates vision and language while preserving coding, tool-use, and productivity performance—another example of the multimodal-agent foundation-model trend. _Source: @alibaba_cloud ([post](https://x.com/alibaba_cloud/status/2062358170815844469))_
- **KV-cache compression (TurboQuant)**: A two-stage KV-cache compression algorithm (Google Research, ICLR 2026) where stage 1 "PolarQuant" converts KV vectors to polar coordinates, unlocking up to 5x more on-device context—a concrete technique for extending context windows on memory-constrained hardware. _Source: @qvac ([post](https://x.com/qvac/status/2061812605077893122))_
- **NVFP4 training stability**: It is now possible to train nanoGPT at NVFP4 precision with training stability matching bf16—a concrete data point that 4-bit-class formats can be made stable for pretraining, not just inference. _Source: @MiniMax_AI ([post](https://x.com/MiniMax_AI/status/2062011402865537124))_
- **Loss-spike stabilizers**: Hyperball, Gated Norm, and Gated Attention are stability techniques that tame "spiky" loss runs during large-model training. _Source: @percyliang ([post](https://x.com/percyliang/status/2062300407683297405))_
- **Hiding GPU bubbles with pipelined decoding**: Moondream's Photon inference engine speeds up inference by up to 35% by using pipelined decoding to fill idle GPU "bubbles"—a practical inference-optimization pattern. _Source: @vikhyatk ([post](https://x.com/vikhyatk/status/2062605085881090256))_
- **Why Muon over Adam**: From a curvature perspective, under a second-order approximation Muon incurs a much smaller curvature penalty than Adam while achieving the same first-order loss decrease—explaining why DeepSeek and Kimi adopted it. Muon specifically optimizes internal 2D weight matrices and is now supported in DeepSpeed. One implementation detail worth knowing: Keller Jordan's Muon carries an extra `max(1, ·)` term relative to muP. _Source: @FengzhuoZhang ([post](https://x.com/FengzhuoZhang/status/2062633213244346374)), @PyTorch ([post](https://x.com/PyTorch/status/2062204026414846240)), @novasarc01 ([post](https://x.com/novasarc01/status/2062182913643561004))_
- **Post-training without distillation**: Microsoft's MAI-Thinking-1 was built "climbing from scratch" with zero synthetic data or distillation from a stronger teacher—reasoning, agentic behavior, and tool use were all learned during post-training ("no cold start")—demonstrating a viable path to a competitive reasoning model independent of an existing frontier model. It also used DSPy's GEPA-optimized LLM judges for pretraining data filtering. _Source: @ying11231 ([post](https://x.com/ying11231/status/2062385980255219844)), @prfsanjeevarora ([post](https://x.com/prfsanjeevarora/status/2062192353968836874)), @lateinteraction ([post](https://x.com/lateinteraction/status/2062015109132873852))_
- **On-policy distillation**: A leading new RL-for-LLMs direction—if a model makes a mistake mid-rollout, you can do targeted on-policy self-distillation to correct it, which fits cleanly into large-scale training pipelines. _Source: @eliebakouch/@dwarkesh_sp ([post](https://x.com/eliebakouch/status/2062364260148126090)), @novasarc01/@srush_nlp ([post](https://x.com/novasarc01/status/2062397008179318804))_
- **Predictable self-distillation (OPSD)**: A "predictive law for on-policy self-distillation" shows final performance is predictable *before* training, holding across models, configurations, and scales (ICML 2026)—useful for budgeting runs without finishing them. _Source: @matteosaponati ([post](https://x.com/matteosaponati/status/2062077763956175326))_
- **RL abstractions are shifting**: If you accept "be as on-policy as possible" as the core RL axiom, the natural design space stops centering on tokens and weights and instead elevates *policies* and the GRPO-style "group" as the unit that matters most—which is why terminology is being reworked. _Source: @srush_nlp ([post](https://x.com/srush_nlp/status/2062512068805152777))_
- **Large-scale RL infra is converging on SGLang + Ray**: Production RL systems (e.g. the "Rocket" design behind MAI-Thinking-1) share a pattern—async RL, separated rollout/inference/learner pools, router-based traffic control, prefix caching, and fault tolerance. Microsoft AI used Ray actors not just for controllers and rollout workers but also as "problem workers" providing sandboxing—finer-grained control than pulling in a third-party sandbox like Modal. _Source: @ying11231 ([post](https://x.com/ying11231/status/2062229342500147267)), @xinyzng ([post](https://x.com/xinyzng/status/2062044488806338791))_
- **Synthetic environments as capability infrastructure**: The MAI report reframes synthetic environments not as evaluation tooling but as capability-building infrastructure; the thesis is that near-term agentic progress will come more from richer synthetic environments than from larger models. Both MAI-Thinking-1 and the open-source Repo2RLEnv turn real code repositories into verifiable RL environments. _Source: @novasarc01 ([post](https://x.com/novasarc01/status/2062080984187851226)), @JongwonPar9958 ([post](https://x.com/JongwonPar9958/status/2062405453125152930))_
- **Length penalty as a reasoning-efficiency reward**: A simple, elegant reward-function design for training reasoning models to be token-efficient—penalize output length directly. _Source: @swyx/@eliebakouch ([post](https://x.com/swyx/status/2062060142489973010))_
- **Open scaling-law ablations**: The Marin project demonstrates a clean, fully open pretraining-ablation methodology (Dense → 129B MoE → architecture/optimizer improvements), similar to MAI's scaling ladder—a reproducible template for studying scaling laws. _Source: @eliebakouch ([post](https://x.com/eliebakouch/status/2062236377991741508))_
- **Data provenance in pretraining**: Known data provenance is treated as genuinely important by practitioners—part of the live debate over why some labs avoid synthetic data in pretraining (concern that it merely teaches "correct formatting"). _Source: @HKydlicek ([post](https://x.com/HKydlicek/status/2062247973636002296)), @soldni ([post](https://x.com/soldni/status/2062250616689459424))_
- **Stateful Visual Encoders (SVE)**: Most open-weight VLMs encode each image independently and defer all comparison to the language model, making them weak at comparative visual reasoning (e.g. "detect the difference" tasks in medicine/science). Post-training cross-attention *between* visual-encoder layers makes the encoder itself change-aware and can be bolted onto existing models. _Source: @berkeley_ai ([post](https://x.com/berkeley_ai/status/2062358241238225125)), ([post](https://x.com/berkeley_ai/status/2062653484584030449))_
- **Visual state tracking as vision's next frontier**: The proposed grand challenge is models that build and maintain an internal world state from incomplete, noisy visual observations—with a new benchmark as a starting line. _Source: @ylecun ([post](https://x.com/ylecun/status/2062541443613270043))_
- **TTS with inline prosody control / streaming**: Higgs Audio v3 is a ~4B TTS model on a Qwen3-4B backbone built for voice AI that "speaks, not reads"—100 languages at single-digit WER/CER with inline control over emotion, style, prosody, and sound effects (open weights). It interleaves text and audio tokens, letting synthesis begin *before* a full sentence arrives—the key architectural trick for low-latency voice agents. _Source: @boson_ai ([post](https://x.com/boson_ai/status/2062629221411995896)), @lmsysorg ([post](https://x.com/lmsysorg/status/2062647691805356464))_
- **Benchmarks should co-evolve with models**: Static benchmarks saturate fast; BenchEvolver automatically evolves saturated problems into harder, *verified* tasks, treating evaluation data as something that should evolve alongside frontier models rather than being fixed. _Source: @berkeley_ai ([post](https://x.com/berkeley_ai/status/2062358478631719262))_
- **Artifact-level coding evals**: ProgramBench scored 0% on frontier models at launch by evaluating at the *artifact* level rather than the code level—a deliberate design choice in the SWE-bench/InterCode lineage to resist saturation. _Source: @stanfordnlp ([post](https://x.com/stanfordnlp/status/2062648936444346408)), @StanfordAILab ([post](https://x.com/StanfordAILab/status/2062297900487754187))_
- **Coding-agent evals are really user-simulation evals**: A useful reframe—coding-agent benchmarks are "customer service evals in disguise." Real value comes from an imperfect user simulator (a user who *doesn't* give a full spec upfront), not a clean spec + codebase. _Source: @arb8020 ([post](https://x.com/arb8020/status/2062252059546542591))_
- **Cheap verifiers as a lever**: Verifiers are LLM judges that check an agent's work; making them dramatically cheaper (Harvey targets ~1,000× cheaper legal verifiers) is framed as "removing stupidity, not adding cleverness." _Source: @arb8020 ([post](https://x.com/arb8020/status/2062278219181490324))_
- **Generation/verification asymmetry runs both ways**: "Verification easier than generation" creates favorable RL/agent dynamics, but the underdiscussed flip side—cases where *generation* is easier than verification—is equally important to reason about. _Source: @thkostolansky ([post](https://x.com/thkostolansky/status/2062092900385837547)), @lateinteraction ([post](https://x.com/lateinteraction/status/2062228181206413625))_
- **The cost geometry of model routing**: Routing the first turn to a cheap model and a later turn to a big model means resubmitting the entire chat history uncached—you pay full price on the escalated turn and lose cache benefits. One mitigation: pick the model once at session start from initial context, or maintain an explicit "worth swapping" cost model, rather than swapping mid-session. _Source: @NickADobos ([post](https://x.com/NickADobos/status/2062029714038853711)), @arb8020 ([post](https://x.com/arb8020/status/2062247144841474052))_
- **Long-horizon agent evals are getting longer**: METR's evals cap at ~16 hours of agent work; Cognition (Cog) now offers private enterprise evals up to 100 hours—covering ML engineering, GPU kernels, and cybersecurity—with a financial guarantee on the results. _Source: @swyx ([post](https://x.com/swyx/status/2062611218196771017)), @eliebakouch ([post](https://x.com/eliebakouch/status/2062703300730876043))_
- **AI in mathematics research**: GPT-5.5 reportedly disproved the sum-product conjecture, and an OpenAI model found a counterexample to an 80-year-old Erdős conjecture—evidence that frontier models can now contribute genuinely novel results when paired with human mathematicians. _Source: @SebastienBubeck ([post](https://x.com/SebastienBubeck/status/2062335588720889866)), @polynoamial/@OpenAI ([post](https://x.com/polynoamial/status/2062668663317246451))_
- **Scarcity of production-grade agentic RL repos**: Despite the hype, open-source agentic-RL repos that pair a real data recipe with production-quality infrastructure are very rare—worth knowing before assuming the ecosystem is mature. _Source: @YichuanM ([post](https://x.com/YichuanM/status/2062070425971298649))_

## Software Engineering

- **Codex's /goal for incremental optimization**: A plain, non-fancy prompt (e.g., "reduce memory by ≥1% without changing build config/allocators or hurting runtime perf") run repeatedly in the background reduced the `ty` type-checker's memory usage by over 10% across releases—a reproducible pattern for agent-driven incremental perf work. _Source: @charliermarsh ([post](https://x.com/charliermarsh/status/2062346195209429153)), ([post](https://x.com/charliermarsh/status/2062345461151797560))_
- **Self-directing agent loops**: A practical agentic pattern in use today—the model writes the plan, runs a swarm of sub-agents, and checks its own work—collapsing plan/execute/verify into one loop. _Source: @StBelkins ([post](https://x.com/StBelkins/status/2062518897988006302))_
- **Subagent "persona" code review**: A practical agent workflow—a Codex skill spawns multiple subagents, each tuned on a specific principal engineer's past code reviews, to review new code from several expert perspectives at once. _Source: @jxnlco ([post](https://x.com/jxnlco/status/2062575512216809908))_
- **Config-file fragmentation across agents**: Codex uses `agents.md` while Claude Code uses `Claude.md`; the lack of a shared standard for agent context files is a real friction point as teams adopt multiple coding agents. _Source: @petergyang ([post](https://x.com/petergyang/status/2062537281693757734))_
- **Measuring AI engineering value, not tokens**: Token usage is a poor proxy for productivity, and a fixed per-person token budget is little better; Cognition built a system to estimate the productive engineering-hours each Devin task delivers, even attaching a financial guarantee. _Source: @ScottWu46 ([post](https://x.com/ScottWu46/status/2062601080744419761)), @ramin_m_h ([post](https://x.com/ramin_m_h/status/2062609990834098593))_
- **Human–agent collaboration is measurable**: "Collaborative Gym" is a framework for enabling and evaluating human-agent collaboration, tested across three tasks (travel planning, related-work writing, tabular analysis)—a concrete harness for studying when humans should stay in the loop. _Source: @stanfordnlp ([post](https://x.com/stanfordnlp/status/2062670467618767173))_
- **Synthetic agent traces for training/testing**: SynthTraces is a minimal harness that generates synthetic coding-agent session traces by having two models converse (one driving, one responding)—a cheap way to produce large volumes of agent-trajectory data. _Source: @ClementDelangue/@julien_c ([post](https://x.com/ClementDelangue/status/2062532012720697793))_

## Security

- **Reused virtual cards expose breaches**: A single-merchant virtual card seeing an unexpected manual-entry charge is a strong signal of a merchant-side data breach—a practical reason to use per-merchant virtual cards (the anomaly is otherwise unattributable). _Source: @SebastianStoll0 ([post](https://x.com/SebastianStoll0/status/2062477186003603908))_
- **`curl | sh` install normalization**: Piping a remote script straight into a shell remains a widely criticized install pattern because it executes unreviewed code with the user's privileges—worth resisting as a default. _Source: @ShamashAran ([post](https://x.com/ShamashAran/status/2062428933656564085))_
- **Upgraded impersonation scams on X**: The "journalist" scam now uses more coherent text, real journalist names, and verified accounts—a reminder that verification badges and plausible prose are no longer reliable authenticity signals. _Source: @eliebakouch ([post](https://x.com/eliebakouch/status/2062686469026709699))_
- **Detect agent misbehavior at the action layer, not the dashboard**: With agents, a prompt-injection / misbehavior can repeat the wrong action tens of thousands of times before a monitoring dashboard surfaces it—argues for verifiable per-action "receipts" rather than after-the-fact aggregate dashboards. _Source: @lagrangedev ([post](https://x.com/lagrangedev/status/2061972756170993978))_

- **GTM is becoming an engineering discipline**: Outbound = agent design, enrichment = retrieval + data quality, attribution = a knowledge-graph problem, forecasting = a modeling problem—reframing go-to-market functions as engineering systems AI engineers can own. _Source: @swyx ([post](https://x.com/swyx/status/2062250212069142881))_

- **"Frontier" branding drives usage independent of quality**: A pointed observation that simply naming endpoints something like "0pus 4.8" or "GPT 5.S" would attract heavy usage regardless of the underlying (open-source) model—a caution about evaluating models by name/marketing rather than benchmarks. _Source: @ClementDelangue ([post](https://x.com/ClementDelangue/status/2062282999396237421))_

## Key Takeaways
