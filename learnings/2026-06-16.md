# Learning Points from the Feed

## AI / Machine Learning

- **Scaling laws under unlimited compute**: A Stanford paper, "Pre-training under infinite compute," reportedly implies an optimal LLM would have on the order of 10.5 quadrillion parameters — a way to reason about where loss curves bottom out when compute is no longer the constraint. _Source: @gabriberton ([post](https://x.com/gabriberton/status/2066294934387450138))_
- **The "infinite compute, finite data" regime**: Compute grows ~4×/year while text data grows only ~3%/year, pushing the field toward a data-bound setting. Where Chinchilla (2022) recommended ~20 tokens per parameter and Llama used up to ~1000, "Pre-training under infinite compute" argues you can profitably train ~35 parameters per token (≈0.03 tokens/param). One implication: reasoning/action traces plus real-world feedback may come to dominate the corpus, with the open internet a vanishing fraction (note: current analyses model pretraining only, excluding RL data). _Sources: @gabriberton ([post](https://x.com/gabriberton/status/2066294936140706256), [post](https://x.com/gabriberton/status/2066294938325917929), [post](https://x.com/gabriberton/status/2066321153078218947)), @JonasMtzgr ([post](https://x.com/JonasMtzgr/status/2066318041445446063))_
- **Ensembles beat single frontier models**: A claimed result argues combinations of models will *always* outperform any single model, which would mean no lab can permanently "own" the frontier. Treat as a strong hypothesis worth checking against the cited work. _Source: @jeremyphoward ([post](https://x.com/jeremyphoward/status/2066052364742934846))_
- **"Distillation" is being used imprecisely**: Distillation is a general post-training technique and should not be conflated with the specific issue of jailbreaking a model's API to extract behavior — two distinct debates that often get merged. _Source: @natolambert ([post](https://x.com/natolambert/status/2066538987100250127))_
- **Self-distillation limits for reasoning models**: Reported finding that self-distillation "does not work for thinking models *yet*," with linked papers — a useful caveat when designing post-training for reasoning models. _Source: @agarwl_ ([post](https://x.com/agarwl_/status/2066670768855859372))_
- **Teacher-merge post-training recipe convergence**: Both NVIDIA's Nemotron 3 Ultra and DeepSeek V4 now use the same pattern — train 10+ specialist "teacher" models, then merge them into a single student via on-policy distillation. The differentiator is "support overlap." _Source: @ziv_ravid ([post](https://x.com/ziv_ravid/status/2066614038373568880))_
- **Not every model uses muP for init**: DeepSeek (v1→v3) and Kimi K2 reportedly do *not* use maximal-update parameterization; they use a naive `N(0, 0.006)` initialization instead, fitting scaling laws to choose batch size and LR — a reminder that widely-discussed scaling techniques aren't universally adopted in production. _Sources: @nrehiew_ ([post](https://x.com/nrehiew_/status/2066615581642743961)), @arb8020 ([post](https://x.com/arb8020/status/2066622120394731534))_
- **LR-schedule lineage**: Mistral's new model reuses essentially the same learning-rate schedule timing as DeepSeek V2 (second phase a slight decay rather than constant, plus a decay cooldown) — evidence of how training recipes are copied and tweaked across labs. _Source: @eliebakouch ([post](https://x.com/eliebakouch/status/2066557152899277185))_
- **Shampoo optimizer tuning**: Shampoo with exponent −1/3 and 0.95 momentum across all accumulators reaches a target ~100–150 steps faster than baseline/Muon configs — a data point in the second-order optimizer debate. _Sources: @_arohan_ ([post](https://x.com/_arohan_/status/2066541004602405157), [post](https://x.com/_arohan_/status/2066540955466117478))_
- **FP8 training is stable**: Side-by-side FP8 vs. BF16 runs produce essentially identical loss curves with no stability issues; the alarming-looking gradnorm metrics are measured *before* clipping. _Source: @hu_yifei ([post](https://x.com/hu_yifei/status/2066637003991716345))_
- **Aggressive LLM quantization preserves usability**: Kimi K2.7's 1T-parameter model was compressed to 325GB (−48%) via "Dynamic 2-bit" quantization — upcasting only important layers to higher precision — enough to run at >40 tok/s on a 330GB setup (full precision needs 610GB). Selective per-layer precision is what makes trillion-parameter models locally runnable. _Source: @ClementDelangue ([post](https://x.com/ClementDelangue/status/2066624094770958477))_
- **Mixed-precision MoE inference**: DeepSeek V4 Pro uses a mixed FP4 + FP8 scheme — MoE expert parameters in FP4, most others in FP8 — illustrating that modern frontier models apply different numeric precision to different parameter classes rather than a single global format. _Source: @paradite_ ([post](https://x.com/paradite_/status/2066378569035686251))_
- **"AI outputs the average of its data" is only true for regression**: The popular claim is accurate for pointwise regression but does *not* describe what likelihood estimation over a categorical distribution actually learns — a common technical overgeneralization. _Source: @kalomaze ([post](https://x.com/kalomaze/status/2066659568537788923))_
- **Teach an LLM to comprehend a token without producing it**: Training with next-token prediction while masking the loss on every occurrence of a specific token (e.g., "Bonjour") yields a model that understands the word but cannot generate it — analogous to passive vs. active language ability. _Source: @gabriberton ([post](https://x.com/gabriberton/status/2066288099102224285))_
- **Sparse-autoencoder "dead features"**: Many SAE features (foundational to mechanistic interpretability) never fire; on some models >70% die even with mitigations like AuxK. An ICML 2026 paper traces this to the geometry of massive activations and proposes a simple fix that improves learned features. _Sources: @james_y_zou ([post](https://x.com/james_y_zou/status/2066626705020891525), [post](https://x.com/james_y_zou/status/2066600077725237714))_
- **Weights can be steganographically programmed**: A model trained on benign-looking Wikipedia articles can have its internal weights covertly forced to encode a fully functional QR code — showing natural-language data can "program" neural-net weights. _Source: @stanfordnlp ([post](https://x.com/stanfordnlp/status/2066672449794850897))_
- **SFT matters more than RLHF for alignment**: DeepMind's interpretability team independently confirmed earlier findings that supervised fine-tuning matters more for alignment than RLHF. _Source: @stanfordnlp ([post](https://x.com/stanfordnlp/status/2066716916665004059))_
- **Video tokens can be drastically compressed**: The CVPR 2026 paper "A Frame is Worth One Token" shows a video frame can be represented with a single token instead of the conventional ~1,024 — a large efficiency gain for video models. _Source: @gabriberton ([post](https://x.com/gabriberton/status/2066703055467536640))_
- **VLM "visual" accuracy often isn't visual**: Testing 8 open vision-language models on 9 VQA benchmarks showed many questions are solvable without ever looking at the image, and some VLMs reason better from text than from pixels — so benchmark scores can overstate genuine visual reasoning. _Source: @harveyiyun ([post](https://x.com/harveyiyun/status/2066500015716028448))_
- **Knowledge staleness is real and game-specific**: Asked a Dota strategy question, Claude Opus 4.6/4.8 recommended an item build invalidated by a 2022 patch, while ChatGPT, Meta AI, and Gemini gave the modern answer — concrete evidence that training-data recency varies sharply across models. _Source: @giffmana ([post](https://x.com/giffmana/status/2066278832655536573))_
- **Text-to-image architectural mismatch**: LLM-powered diffusion models typically encode the prompt only once, while the evolving noisy latent is handled by a separately trained generative backbone — a design gap newer work probes by reusing the pretrained LLM throughout generation. _Source: @xichen_pan ([post](https://x.com/xichen_pan/status/2066693080757997794))_
- **Tversky Neural Networks**: Code for Tversky Neural Networks (ICLR 2026) is now a public PyPI library with reproducible experiments — a design drawing on Tversky's psychological similarity model rather than standard metric distances. _Source: @stanfordnlp ([post](https://x.com/stanfordnlp/status/2066671999590797658))_
- **Evaluating LLM agents has three grading strategies**, with human evaluation as the definitive ground truth — start from quick manual inspection before scaling to automated methods. _Source: @cwolferesearch ([post](https://x.com/cwolferesearch/status/2066632256739848640))_
- **Much "robotics RL" is imitation learning in disguise**: Reward shaping, curricula, initialization, and environment design are indirect ways of providing human demonstrations; behavior cloning, DAgger, and on/off-policy RL are expressions of the same problem. The genuinely hard, unsolved part is exploration. _Sources: @realyunlong ([post](https://x.com/realyunlong/status/2066386255353725181)), @ryancjulian ([post](https://x.com/ryancjulian/status/2066623865397399608))_
- **World/Action models vs. VLAs aren't rivals**: World-Action Models (WAMs) are emerging as a second recipe for robot foundation models distinct from Vision-Language-Action (VLA) models, but the apparent rivalry reflects a temporary difference in emphasis — the two are likely to be unified. _Sources: @NVIDIAAI ([post](https://x.com/NVIDIAAI/status/2066562105357353022)), @prime_cai ([post](https://x.com/prime_cai/status/2066650671240351744))_
- **The robotics "data wall" is falling**: Robots can now learn from human video, practice in simulation before touching reality, and there's finally enough data — breaking the slow, expensive, narrow teleoperation bottleneck. _Source: @brianzhan1 ([post](https://x.com/brianzhan1/status/2066599756361789592))_
- **Agent architectures are evolving past loops**: A progression from Loops → Graphs → Programs, where the execution graph itself is generated at runtime, is one proposed direction beyond today's agent loops. _Source: @santoshradha ([post](https://x.com/santoshradha/status/2066515938204082538))_
- **DSPy programming model**: DSPy reframes LLM applications as systems of API calls stitched together through declared input/output signatures, with a built-in way to test each stage — making prompt pipelines modular and measurable rather than monolithic. _Source: @lateinteraction ([post](https://x.com/lateinteraction/status/2066318520506286237))_
- **Retrieve-then-filter retrieval**: A simple "retrieve top-1k with embeddings, then filter with a strong LLM (GPT-5.5)" pipeline shows a clear quality signal on the OBLIQ-bench WildChat split — embeddings for recall, LLM for precision. _Source: @lateinteraction ([post](https://x.com/lateinteraction/status/2066596467679105040))_
- **Structured harnesses beat dumping context**: An RLM agent processed ~80k lines of CloudWatch logs (≈8M tokens) but, after 53 steps, had spent only ~32k "active" tokens — because good harness design retrieves structured information on demand instead of stuffing everything into context. _Sources: @lateinteraction ([post](https://x.com/lateinteraction/status/2066235710395351353), [post](https://x.com/lateinteraction/status/2066641123863413173))_
- **Agentic-RL bottlenecks for CLI agents**: Two distinct problems — surfacing useful information in huge workspaces, and assigning fine-grained credit from coarse episode-level rewards. The σ-Reveal and A3 methods target each respectively. _Source: @HaoyangSu_ ([post](https://x.com/HaoyangSu_/status/2053836907449057377))_
- **Streaming speech-model state of the art**: Cartesia's Sonic 3.5 (TTS) and Ink-2 (STT) topped streaming-audio leaderboards after ~5 months of work — evidence that fully streaming audio models can lead on quality, not just latency. Sonic 3.5 targets sub-90ms latency, native support for 42 languages, context-aware homograph pronunciation (read, bass, bow), and accurate reading of codes/IDs/structured text. _Sources: @krandiash ([post](https://x.com/krandiash/status/2066559212533190917)), @tri_dao ([post](https://x.com/tri_dao/status/2066674270676398177)), @togethercompute ([post](https://x.com/togethercompute/status/2066628181684105480)), @realDanFu ([post](https://x.com/realDanFu/status/2066581877268644041))_
- **Coding-specialized agentic models**: Kimi-K2.7-Code (built on Kimi K2.6) is purpose-built for long-horizon, tool-heavy software workflows, and its "HighSpeed" variant reports up to ~180 tok/s on median-length coding inputs and 260 tok/s on shorter contexts (~6× faster) — illustrating the trend toward models tuned for agentic coding plus the throughput tradeoffs involved. _Sources: @Kimi_Moonshot ([post](https://x.com/Kimi_Moonshot/status/2066467110960959833)), @tri_dao ([post](https://x.com/tri_dao/status/2066048183080550789))_

## Software Engineering

- **Cap agent diff size to force decomposition**: Any agent-generated diff over ~1500 lines is probably too big and signals the task should be broken down — paired with a "draw the owl" loosely-guided first pass. _Source: @mitchellh ([post](https://x.com/mitchellh/status/2066645959539556852))_
- **"If it works, who cares" is a trap for agents**: That mindset assumes the agent perfectly understands what "works" means, but specs are usually underspecified and agents make bad assumptions — so code quality and clarity still matter. _Source: @mitchellh ([post](https://x.com/mitchellh/status/2066657032938442833))_
- **Read your own code**: LLM coding agents routinely fabricate and guess at how code works, so relying on them without reading the actual code leads to confidently wrong changes — understanding your codebase remains non-negotiable. _Source: @arb8020 ([post](https://x.com/arb8020/status/2066670479167942786))_
- **Preserve agent traces**: Coding-agent reasoning/action logs are valuable training and debugging data and a scarce corpus — keep them rather than discarding them. _Source: @julien_c ([post](https://x.com/julien_c/status/2066056789003534541))_
- **Sandbox-executing code review**: Greptile's "t-rex" runs a PR branch in a sandbox — mocking API calls, clicking the UI, writing/running unit tests — and reportedly caught ~20% more bugs than static review, showing the value of execution-based (vs. read-only) review. _Source: @dakshgup ([post](https://x.com/dakshgup/status/2066536928716235254))_
- **Let agents parse ASTs, not grep**: For a query like finding `[key: foo | bar]` usages, grep produced too many false positives, so Codex independently wrote a script to parse each file's AST and return precise locations — structured parsing beats text search for code-aware tasks. _Source: @charliermarsh ([post](https://x.com/charliermarsh/status/2066214744978063786))_
- **AI coding tools amplify focus, not substitute for it**: They feel like "a mech suit" when you already know what you want and are locked in, and "meh" otherwise — the bottleneck is operator clarity, not the tool. _Source: @GergelyOrosz ([post](https://x.com/GergelyOrosz/status/2066607845768896835))_
- **Realistic AI productivity gains for SWEs**: A grounded estimate puts AI coding assistance at a net ~30% gain after accounting for review and slop cleanup — not the "10×" often claimed. _Source: @benjamin_horne ([post](https://x.com/benjamin_horne/status/2066548204141727962))_
- **LLM workflows decay fast**: Even a few-weeks-old way of working with LLMs already feels tedious and manual — expect to continuously re-automate your own process as capabilities advance. _Source: @charliermarsh ([post](https://x.com/charliermarsh/status/2066228233398264203))_
- **"Agent workflows" are often deterministic orchestration in disguise** — boxes-and-arrows pipelines dressed up with AI rather than genuinely agentic behavior. A useful lens for evaluating agent-product claims. _Source: @sema4ai ([post](https://x.com/sema4ai/status/2054612515435282470))_
- **Code beats visual builders because logic, not syntax, is the hard part**: No-code tools removed syntax, but complex automation still needs loops, branching, and state — and expressing that as a script means you can grep, diff, and roll it back, which a visual canvas can't. _Source: @aisle_sh ([post](https://x.com/aisle_sh/status/2062952515247734800))_
- **torch.compile integer-division gotcha**: In plain Python `10 - step / 100` (step=1) is 9.99, but under torch.compile the same expression returns 9 — a silent type/precision divergence to watch for when compiling numeric code. _Source: @bozavlado ([post](https://x.com/bozavlado/status/2066543360098152799))_
- **Linter performance and the Rust React compiler**: Oxlint is being made 50%–2× faster specifically to offset the cost of the Rust port of the React compiler — a concrete look at the perf budgeting behind JS tooling. _Source: @boshen_c ([post](https://x.com/boshen_c/status/2066528313154347095))_
- **Responsiveness ≠ raw speed**: Users don't care about async/await; they care that the app never freezes — frame UI work around perceived responsiveness and avoid main-thread blocking. _Source: @twannl ([post](https://x.com/twannl/status/1979605647311188138))_
- **Self-healing docs**: Documentation sites can close their own coverage gaps — a user's question is logged, the gap flagged, and a fix auto-drafted, turning support queries into doc improvements. _Source: @mintlify ([post](https://x.com/mintlify/status/2062254243999035600))_
- **Low-latency voice infra is now an afternoon's work**: An open-source voice SDK plus a real phone number can deliver an AI receptionist with ~412ms to first audio. _Source: @frank__rosh ([post](https://x.com/frank__rosh/status/2066605965588287817))_
- **The biggest challenge in computing is people and communication, not machines** — a lesson SWEs learn the hard way, now playing out even at frontier labs negotiating with government. _Source: @GergelyOrosz ([post](https://x.com/GergelyOrosz/status/2066636899616174140))_
- **Know your notation: "iff"** is standard shorthand for "if and only if," not a typo — learn domain conventions before assuming a tool erred. _Source: @traits_reality ([post](https://x.com/traits_reality/status/2066292259037778365))_

## Systems & Infrastructure

- **Speculative decoding leap (DFlash + Spec V2)**: Integrating the DFlash method — block-diffusion drafting plus KV injection (rather than a separate aligned draft model), with a trained drafter for Qwen 397B-A17B — into SGLang's new Spec V2 overlap scheduler yields >4.3× throughput over baseline and ~1.5× over native MTP at equal quality. Speculative decoding is now the default engine in SGLang. _Sources: @lmsysorg ([post](https://x.com/lmsysorg/status/2066560651942863297)), @modal ([post](https://x.com/modal/status/2066558831099093401)), @BanghuaZ ([post](https://x.com/BanghuaZ/status/2066562506076889169)), @ying11231 ([post](https://x.com/ying11231/status/2066562437659468164)), @zhijianliu_ ([post](https://x.com/zhijianliu_/status/2066558967464239299))_

Most KV-cache research (e.g., eviction papers) is algorithmic, but those gains only materialize if the underlying systems support them. _Sources: @togethercompute ([post](https://x.com/togethercompute/status/2066204867954114908)), @WeianMaoX ([post](https://x.com/WeianMaoX/status/2066570799843287397)), @songhan_mit ([post](https://x.com/songhan_mit/status/2066573661016907993))_

The indexer rewrite was the biggest single win. _Source: @togethercompute ([post](https://x.com/togethercompute/status/2066672024165274064))_
- **vLLM v0.23.0 serving internals**: Real techniques worth knowing — TRTLLM-gen attention kernel, sparse-MLA decoupling, EPLB for large-MoE load balancing, a new default Model Runner V2 for dense Llama/Mistral, FP8 FlashInfer attention for ViT, Triton MoE on Hopper by default, a CUTLASS FP8 scaled-mm padding bypass (+20%), MoE-permute buffer pre-allocation (+9–14%), NUMA auto-binding on DGX B300, and AMD native W4A16 / fused-MoE W4A16 kernels on ROCm 7.2.3. _Sources: @vllm_project ([post](https://x.com/vllm_project/status/2066401110580228543), [post](https://x.com/vllm_project/status/2066401115089121653))_

- **Prefill-decode (PD) disaggregation is high-risk, high-reward**: One of the hardest serving techniques to get right; throughput wins are real but only materialize in the right settings — validated on AMD MI325X with Ray Serve + vLLM. _Source: @vllm_project ([post](https://x.com/vllm_project/status/2066657535743201431))_

## Science & Research

- **Reproducibility is genuinely hard to define**: There's an active debate over whether papers without released code should be accepted at venues like CVPR. A proposal would tie best-paper awards to available code; counterpoints note some institutions legally can't release code yet still do valuable work, and the line between "reproducible" tiers (open weights vs. eval code vs. training code vs. data) is hard to draw. Real-world uptake (e.g., MegaLoc adopted in industry) is argued to be a stronger validation signal than citations alone. _Sources: @gabriberton ([post](https://x.com/gabriberton/status/2066312123282780575), [post](https://x.com/gabriberton/status/2066312124754960731), [post](https://x.com/gabriberton/status/2066296598326636714))_

- **Always cite prior art for "novel" losses**: Meta's Xray-Visual Models paper's "introduced" siamese loss (noisy web caption + synthetic caption) was actually introduced earlier by the TIPS paper — trace technique provenance in the literature. _Source: @gabriberton ([post](https://x.com/gabriberton/status/2066290370473013369))_
- **LLMs as math-research collaborators**: A researcher reports solving an open min-max/saddle-point optimization problem with ChatGPT Pro — a concrete example of frontier models contributing to novel proofs. _Source: @bremen79 ([post](https://x.com/bremen79/status/2066537769829122186))_

## Key Takeaways

1. **Inference is now a first-class systems discipline.** The biggest serving wins come from KV-cache management, kernel rewrites/fusion, speculative decoding (DFlash + Spec V2 hitting >4.3× baseline, now SGLang's default), and PD disaggregation — not from the weights. _Sources: @togethercompute ([post](https://x.com/togethercompute/status/2066672024165274064)), @modal ([post](https://x.com/modal/status/2066558831099093401)), @vllm_project ([post](https://x.com/vllm_project/status/2066657535743201431))_
2. **The compute-vs-data balance is inverting.** With compute growing ~4×/yr and text ~3%/yr, the field is moving toward an "infinite compute, finite data" regime that overturns Chinchilla-era token-per-parameter rules (now ~35 params/token) and elevates agent traces and real-world feedback as the dominant training signal. _Sources: @gabriberton ([post](https://x.com/gabriberton/status/2066294936140706256)), @JonasMtzgr ([post](https://x.com/JonasMtzgr/status/2066318041445446063))_
3. **Inference economics are the new model-selection battleground.** Token spend now rivals engineering headcount (70% of eng leaders doubled it in six months), an in-house router can halve a $100k/month bill, and DeepSeek V4 Pro delivers comparable intelligence 20–40× cheaper than frontier US models via selective-precision quantization — cost-per-task, driven by serving efficiency, is becoming decisive. _Sources: @tecoker ([post](https://x.com/tecoker/status/2066626599466791296)), @ArtificialAnlys ([post](https://x.com/ArtificialAnlys/status/2066700137985081738)), @ClementDelangue ([post](https://x.com/ClementDelangue/status/2066624094770958477))_
4. **Don't outsource understanding to agents — verify rigorously.** Coding agents fabricate how code works and act on underspecified specs, so reading your own code, capping diffs (~1500 lines), and leaning on execution/sandbox-based review matter more, not less. Realistic SWE gains are ~30%, not 10×. _Sources: @arb8020 ([post](https://x.com/arb8020/status/2066670479167942786)), @mitchellh ([post](https://x.com/mitchellh/status/2066657032938442833)), @dakshgup ([post](https://x.com/dakshgup/status/2066536928716235254)), @benjamin_horne ([post](https://x.com/benjamin_horne/status/2066548204141727962))_
5. **Platform-dependency risk is real, and the AI labor market is barbell-shaped.** Anthropic's no-warning Agent SDK / `claude -p` pricing move (then partial reversal) is a cautionary tale for anyone building on another company's generous tier — while frontier labs hire senior infra engineers (median ~12 yrs, few juniors/PhDs) as university CS enrollment craters ~42–61% YoY. _Sources: @GergelyOrosz ([post](https://x.com/GergelyOrosz/status/2066710966583132413)), @teortaxesTex ([post](https://x.com/teortaxesTex/status/2066461308401168577)), @itsandrewgao ([post](https://x.com/itsandrewgao/status/2066616607850586264))_
