# Learning Points from the Feed

## AI / Machine Learning

- **Agent "loop engineering"**: Getting AI agents to iterate at length — running a model in a controlled loop so it can build software over many steps — has emerged as a distinct engineering discipline (popularized by the creators of Claude Code and OpenClaw). _Source: @AndrewYNg ([post](https://x.com/AndrewYNg/status/2071988145667928442))_
- **Diffusion LMs via model-splitting**: NVIDIA's Nemotron-Labs-TwoTower adapts a 30B autoregressive MoE into a diffusion LM by splitting it in two — one half holds context while the other writes tokens in parallel, breaking the one-token-at-a-time bottleneck. _Source: @NVIDIAAI ([post](https://x.com/NVIDIAAI/status/2072394812301480067))_
- **Multi-token prediction ported to diffusion**: MTP speeds up autoregressive LLMs; new Multi-Token Residual Prediction (MRP) work explores whether the same trick accelerates diffusion LMs by training a head to predict residuals rather than the full next denoising step. _Source: @charles_irl ([post](https://x.com/charles_irl/status/2072506221408751944))_
- **Faster agent web-reading through pipeline design**: Large speed/cost wins (~60× faster, ~49× cheaper) came not from a better model but from architecture — scraping backends hand clean content straight to the agent, and large pages are cached locally and paged on demand rather than reprocessed. _Source: @NousResearch ([post](https://x.com/NousResearch/status/2071974594961977727))_
- **GANs can be scaled with the right setup**: "Scalable GANs with Transformers" shows GANs — long considered finicky and abandoned for diffusion — can be trained stably and scaled, reviving an architecture many wrote off. _Source: @jm_alexia ([post](https://x.com/jm_alexia/status/2072010528407318831)), @zhaisf ([post](https://x.com/zhaisf/status/2072230656466387125))_
- **Sparse attention methods are largely recombinations**: New sparse-attention designs (e.g. in LongCat-2.0) mostly reuse existing components — DeepSeek Sparse Attention's top-k indexer being a common building block — inviting the observation that they resemble classic information-retrieval ideas. _Source: @eliebakouch ([post](https://x.com/eliebakouch/status/2071795846195433862)), @lateinteraction ([post](https://x.com/lateinteraction/status/2071799167630946719))_
- **Portable fine-tuning adapters (PorTAL)**: A recipe to cheaply transfer a fine-tune from one base model to the next, matching per-task LoRA accuracy at ~half the cost — attacking the economics problem that any custom model risks obsolescence when a better base ships weeks later. _Source: @RampLabs ([post](https://x.com/RampLabs/status/2072383318516187380)), @eglyman ([post](https://x.com/eglyman/status/2072391940834824522))_
- **When fine-tuning still beats prompting**: With the right data — e.g. expert human judgments — fine-tuning can beat prompt-only approaches by a large margin, as shown by Bridgewater fine-tuning Qwen3-235B to triage which financial documents merit an analyst's time. _Source: @johnschulman2 ([post](https://x.com/johnschulman2/status/2072132258463719658)), @alexolegimas ([post](https://x.com/alexolegimas/status/2072403354433601936))_
- **Retrieval doesn't replace pretraining**: Search access (RAG, agentic RAG, long context) does not outdo having actually learned the domain during pretraining — retrieval augments but doesn't substitute for internalized knowledge. _Source: @lateinteraction ([post](https://x.com/lateinteraction/status/2072412513552015562))_
- **Midtraining is "pretraining with better data"**: Concretely — longer-context data (e.g. 4k→32k), data more similar to evals (code, math) over low-information text, and cleaner/more-filtered data (sometimes rubric-scored). _Source: @gabriberton ([post](https://x.com/gabriberton/status/2071813701032952230), [post](https://x.com/gabriberton/status/2072127298690810265))_
- **Transformer position encodings**: In basic attention every token attends to every other with no inherent order — the sequence is a bag; transformers recover order only by explicitly adding position encodings to token representations. _Source: @ID_AA_Carmack ([post](https://x.com/ID_AA_Carmack/status/2072299027157123443))_
- **Code as a flattened AST**: Textual source is a linear flattening of an abstract syntax tree; since LLMs emit tokens linearly with only linear context connections, there may be advantages to reasoning in a richer structural representation than raw text. _Source: @ID_AA_Carmack ([post](https://x.com/ID_AA_Carmack/status/2072152520374280269)), @Devon_Eriksen_ ([post](https://x.com/Devon_Eriksen_/status/2072226844938485784))_
- **InstructGPT's RLHF sizing**: InstructGPT used comparatively small 6B reward models and value functions to run PPO on the full 175B GPT-3 — critic/reward networks need not match the policy's scale. _Source: @stochasticchasm ([post](https://x.com/stochasticchasm/status/2071878097285333215))_
- **Code world models**: A coding agent resembles an embodied agent whose "world" is its harness (e.g. the terminal); evidence suggests learning a model of that world improves agent performance. _Source: @cwolferesearch ([post](https://x.com/cwolferesearch/status/2071991108784001447))_
- **The scaffold/harness effect**: In coding agents, the harness can matter as much as the underlying model for both tokens burned and success rate ("The Scaffold Effect in Coding Agents"). Related: a meta-agent supervising runs catches confident-but-wrong trajectories and roughly doubles autonomous throughput. _Source: @SentientAGI ([post](https://x.com/SentientAGI/status/2071956989434040549)), @chrmanning ([post](https://x.com/chrmanning/status/2072421282860454065))_
- **Skills as trainable objects**: Microsoft's SkillOpt turns manual "skill"/instruction editing for agents into an optimization process, improving reliability without changing model weights. _Source: @MSFTResearch ([post](https://x.com/MSFTResearch/status/2072001556463886840))_
- **Automated synthetic-data generation**: Meta's Autodata is a framework where an AI agent iteratively creates, evaluates, and refines synthetic training data — targeting the high-quality-data bottleneck. _Source: @cwolferesearch ([post](https://x.com/cwolferesearch/status/2072493331842576774))_
- **KV cache compaction**: Compressing the KV cache during long-context inference (STILL and others) is an active, practical area for cutting memory/latency without full recompute — relevant to serving long-context/agentic workloads. _Source: @cwolferesearch ([post](https://x.com/cwolferesearch/status/2072435980494119136))_
- **Muon's hidden cost**: Beyond faster training, the Muon optimizer appears to lose plain gradient descent's "simplicity bias," which can hurt generalization — optimizer choice trades off more than convergence speed. _Source: @jeremyphoward ([post](https://x.com/jeremyphoward/status/2072456367177441539))_
- **PPO vs GRPO by horizon**: PPO's advantage over GRPO grows with task horizon — longer horizons make reward sparser (demanding larger group sizes for GRPO), whereas PPO supplies better long-horizon signal. Long-horizon agents likely need an amortized credit-assignment model over *partial* trajectories, which a critic-based PPO setup can learn from rollout fragments. _Source: @Grad62304977 ([post](https://x.com/Grad62304977/status/2072206041094443142)), @novasarc01 ([post](https://x.com/novasarc01/status/2072210083887698133))_
- **Defining hallucination precisely**: A Stanford position paper argues hallucination isn't just "wrong facts" but *inaccurate internal world modeling*, proposing a unified formal definition — reframing from output errors to representation errors. _Source: @StanfordAILab ([post](https://x.com/StanfordAILab/status/2072145464028442644))_
- **JEPA anti-collapse regularization scales**: VISReg/SIGReg (regularization-based JEPA) prevents embedding collapse (high gradient when embeddings collapse) at linear complexity and matches DINOv2 while training on ~10× less data (ImageNet-22k vs LVD-142M). Inverse dynamics modeling (IDM) can also regularize but is weaker — it only captures what the agent's actions affect. _Source: @ylecun ([post](https://x.com/ylecun/status/2072111865472197098), [post](https://x.com/ylecun/status/2072111978693210419), [post](https://x.com/ylecun/status/2072396831024173313))_
- **Test-time adaptation in world models**: AdaJEPA acts, compares predicted vs. observed latent state, and adapts at test time (akin to model-predictive control / meta-learning) — pushing self-supervised world models toward closed-loop control. _Source: @ylecun ([post](https://x.com/ylecun/status/2072337476748808365))_
- **Small models can win on narrow tasks**: On Liquid's open IFStruct structured-output benchmark, a 350M model beats models 10×+ its size. The benchmark deliberately presents requirements as messy real prompts (chat, bullet lists, raw JSON Schema, annotated YAML, ASCII tables) and scores binary field/type/enum/bound correctness — since real structured-output requests are far messier than clean schema benchmarks assume. _Source: @liquidai ([post](https://x.com/liquidai/status/2071957538086506762), [post](https://x.com/liquidai/status/2071957540116508788), [post](https://x.com/liquidai/status/2071957541681008643)), @ramin_m_h ([post](https://x.com/ramin_m_h/status/2071984859573281227))_
- **Constrained decoding ≠ good JSON**: Even with grammar-constrained generation, the model still needs meaningful logits over admissible next tokens to produce *useful* JSON — schema conformance guarantees syntax, not content quality. _Source: @mlech26l ([post](https://x.com/mlech26l/status/2072091956562542962))_
- **Prompt optimization for intent detection**: Applying GEPA to a small Qwen 4B got "ask detection" (extracting intention/deliverable from a Slack message) working well — small models + optimized prompts can handle structured extraction. _Source: @lateinteraction ([post](https://x.com/lateinteraction/status/2072131488368181301))_
- **The pre-classifier trap**: Routing "simple" tasks to a cheaper model doesn't work reliably, because knowing a task is simple essentially requires solving it first. The workable pattern is an *advisory* model that attempts the task and signals confidence. _Source: @MParakhin ([post](https://x.com/MParakhin/status/2072275413116784961))_
- **Model-routing as a customization layer**: Open-source routers (e.g. vLLM's semantic router) direct queries across models; the future is multi-model, with the router customized like your own code — a likely locus of value capture. _Source: @ClementDelangue ([post](https://x.com/ClementDelangue/status/2071987200481202217))_
- **Most queries don't need a frontier model**: A Stanford study found 71.3% of ChatGPT queries could be accurately answered by a local model — implying much enterprise/on-device load could run locally at far lower cost. _Source: @ClementDelangue ([post](https://x.com/ClementDelangue/status/2071962840236282024)), @devdigest ([post](https://x.com/devdigest/status/2071970516471021931))_
- **GLM-5.2 — capability and verbosity move together**: From GLM-5.1→5.2 the Artificial Analysis Intelligence Index jumped 11 points (40→51) while reasoning-token share rose 92%→95% and output tokens to run the index rose ~122M→141M (~1.8× the average model) — more reasoning cost buys more capability. _Source: @ArtificialAnlys ([post](https://x.com/ArtificialAnlys/status/2072022576394821859), [post](https://x.com/ArtificialAnlys/status/2072022579007947013))_
- **Frontier physics is still hard for LLMs**: On CritPt (built by Argonne/UIUC with 60+ researchers), even top models score only ~21% (GLM-5.2 ties Claude Opus 4.8) — reasoning gains matter most on genuinely hard scientific problems. _Source: @ArtificialAnlys ([post](https://x.com/ArtificialAnlys/status/2072022581457436771))_
- **Benchmarks are saturating → multi-turn**: Single-turn coding/agent benchmarks have topped out; the field is moving to multi-turn benchmarks like SWE-Together / SWE-Interact, built from real user–agent sessions where the spec emerges mid-task — closer to how coding help actually works. _Source: @ShirleyYXWu ([post](https://x.com/ShirleyYXWu/status/2072370459266695319)), @jeremyphoward ([post](https://x.com/jeremyphoward/status/2072273568570982900)), @arb8020 ([post](https://x.com/arb8020/status/2072073710882726245))_
- **ParallelKernelBench**: An open benchmark for whether LLMs can write *fast* CUDA kernels for real communication-heavy multi-GPU workloads — much harder than single-kernel generation. _Source: @realDanFu ([post](https://x.com/realDanFu/status/2072198405330215075))_
- **ARC-AGI-3 raises the bar**: Agentic, with no explicit rules or goals — they must be discovered — which is why it stumps approaches that beat all prior ARC benchmarks. _Source: @fchollet ([post](https://x.com/fchollet/status/2072337007549014194))_
- **Open models leading specific categories**: GLM-5.2 became the first open-source model to lead an APEX-SWE category (55.3% Pass@1 on Integration, top open-or-closed), while ranking 6th overall (37.3%) — the open/closed gap is closing in targeted domains. _Source: @JosephJacks_ ([post](https://x.com/JosephJacks_/status/2072485909141110861))_
- **AI-run hyperparameter search converges**: Across 461 experiments, an "AutoScientist" repeatedly converged on the same high-impact hyperparameters — much manual tuning is rediscovering a stable optimum. _Source: @adaption_ai ([post](https://x.com/adaption_ai/status/2072290093897818613))_
- **Weight sync in RL is a compressible problem**: RL weight sync looks RDMA-bound, but since >99% of BF16 weights are byte-identical step to step, shipping only the delta cuts traffic ~100–1000× (bit-exact) — turning a hardware bottleneck into a software one and enabling RL over commodity ethernet. _Source: @ramin_m_h ([post](https://x.com/ramin_m_h/status/2071912978769744178))_
- **Why 4-bit is hard**: FP4 has only 15 representable values, making scaling choices critical; NVFP4 uses smaller blocks and finer-grained scaling, pushing FP4 from a compression trick toward a real training/inference primitive for LLMs and diffusion. _Source: @songhan_mit ([post](https://x.com/songhan_mit/status/2071988581237748093))_
- **Data quality beats quantity**: A t-shirt-folding robot got *worse* with extra demonstrations — not because the data was bad (every demo ended folded) but because it was *noisy*; WARP-RM is a reward model for curating it. Similarly, pre-pretraining LLMs on neural cellular automata beat even 10× more natural-language pre-pretraining. _Source: @berkeley_ai ([post](https://x.com/berkeley_ai/status/2072112681218421133)), @josh_wills ([post](https://x.com/josh_wills/status/2072357728069255528))_
- **Self-evolving robot skill libraries (ASPIRE)**: Coding agents observe multimodal sensory traces from sim and real robots to build a compounding skills library — a robot solving its 100th task is no longer as naive as at its first. _Source: @DrJimFan ([post](https://x.com/DrJimFan/status/2072004190856212902), [post](https://x.com/DrJimFan/status/2072337488782475390))_
- **Pretraining motor control (GPC)**: NVIDIA's Generative Pretrained Controllers turn motor skills into a vocabulary of discrete tokens, testing whether motor control itself can be pretrained and reused across tasks instead of hand-building one controller per task. _Source: @NVIDIAAI ([post](https://x.com/NVIDIAAI/status/2072069361792413878)), @arb8020 ([post](https://x.com/arb8020/status/2072416250999758996))_
- **Consumer-GPU world models**: Waypoint-1.5 is a real-time video-diffusion world model engineered to run on consumer GPUs, pushing interactive world models toward accessible deployment. _Source: @overworld_ai ([post](https://x.com/overworld_ai/status/2072120615251968222))_
- **MiniMax M3 design details**: The open-weight M3 uses sparse attention (reportedly an intern's idea) and "native" multimodality (trained multimodal from the start). At 400B+ params the unquantized weights need a full HGX B200 node, and MXFP4 quantization reportedly won't run on Hopper. _Source: @MiniMax_AI ([post](https://x.com/MiniMax_AI/status/2072171116055961767)), @LambdaAPI ([post](https://x.com/LambdaAPI/status/2072024926580769189))_
- **Anthropic naming maps to poetry length**: Haiku (short/fast), Sonnet (mid-tier, 14-line classic), Opus (largest/most capable, a full composition) — a mnemonic for the capability/latency tradeoff. _Source: @singularity_adj ([post](https://x.com/singularity_adj/status/2072324396035842086))_
- **The inference bottleneck may flip to compute-bound**: A contrarian view — LLM inference (even decoding) may become compute-bound rather than memory-bound, undercutting custom chips designed around today's memory-bound MoE decoding. ## Software Engineering

- **High-frequency deployment at scale**: Spotify ships ~4,500 production deploys a day with 73% automated — a benchmark for mature continuous deployment (and a reminder that deploy frequency ≠ visible product improvement). _Source: @mitchellh ([post](https://x.com/mitchellh/status/2071971627748020409)), @amix3k ([post](https://x.com/amix3k/status/2072176362769592432))_
- **Verify agent-proposed optimizations under realistic conditions**: An agent (Codex) reported making uv's uncached dependency resolutions >40% faster via smarter request scheduling — but honest retesting showed the speed-up *did not hold* under reliable network conditions. Benchmark agent wins under representative, not just favorable, conditions. _Source: @charliermarsh ([post](https://x.com/charliermarsh/status/2072414043965399376), [post](https://x.com/charliermarsh/status/2072472774099022240))_
- **Rewriting hot inner loops in Rust as a Spark optimization**: Identify a Spark job's bottleneck, then have a coding agent rewrite the heavy inner worker logic in Rust, accumulating incremental 1–2% speedups over time. _Source: @charliermarsh ([post](https://x.com/charliermarsh/status/2072007955789107573))_
- **The "zero, one, or unlimited" rule**: Supporting exactly *two* of something almost always leads to needing three — the moment you need more than one, design for unlimited rather than a fixed small count. _Source: @swyx ([post](https://x.com/swyx/status/2072476052518244601))_
- **Debugging as a transferable skill**: A `SKILL.md` distilled from the open "Art of Debugging" book can materially improve an AI assistant at Unix/Python/PyTorch debugging; the methodology chapter is framework-agnostic. _Source: @StasBekman ([post](https://x.com/StasBekman/status/2072375437381284154))_
- **Filtering models by hardware**: Hugging Face now lets you filter models by what actually fits/runs on your specific GPU, CPU, or Apple Silicon — closing the gap between "model exists" and "model runs on my box." _Source: @Thom_Wolf ([post](https://x.com/Thom_Wolf/status/2071982536402882770)), @ClementDelangue ([post](https://x.com/ClementDelangue/status/2071945114130293085)), @julien_c ([post](https://x.com/julien_c/status/2071955755805138996))_
- **LLM-as-a-Docker-container for eval speed**: `wmh` (world-model-harness) turns agent traces into a faithful replica of a production environment by having an LLM impersonate a Docker container — ~5× faster than the real container on SWE-bench tasks. _Source: @cudagdb ([post](https://x.com/cudagdb/status/2072007252463247610))_
- **Skeletonization as set-cover on GPU**: In shape skeletonization / medial-axis extraction, the point-selection step is a set-cover problem; solving it exactly on the GPU (Coverage Axis) gives the same optimal selection with large speedups. _Source: @frankzydou ([post](https://x.com/frankzydou/status/2072399917935722699))_
- **Audit the measurement code, not just headline numbers**: A close read of a paper's supplementary code showed reported results may undercount a competitor's ("Goose") token usage by ~6.6×. _Source: @gneubig ([post](https://x.com/gneubig/status/2071976757574701403))_
- **PyPI's 100MB package limit**: PyPI enforces a 100MB package size cap — a real obstacle for bundling AOT-compiled kernels into a wheel. _Source: @vikhyatk ([post](https://x.com/vikhyatk/status/2072432643279609857))_
- **Triangle ordering affects GPU performance**: Beyond raw triangle count, the *ordering* of triangles materially impacts rendering performance — surfaced alongside Earcut's refresh (now ~55% faster on average, up to 3×). _Source: @ID_AA_Carmack ([post](https://x.com/ID_AA_Carmack/status/2072320234619355572))_
- **Rust ML framework tradeoffs**: Burn (Tracel AI) is a Rust deep-learning framework; a noted limitation is that it's Rust-only with no Windows support — language and platform coverage are real adoption constraints for ML tooling. _Source: @JosephJacks_ ([post](https://x.com/JosephJacks_/status/2072386911398998495)), @MParakhin ([post](https://x.com/MParakhin/status/2072438802384097591))_
- **DuckLake + DuckDB for bulk data**: For importing large datasets (e.g. exported health data), pairing DuckLake with DuckDB gives an agent a fast, queryable local store — a lightweight alternative to heavier warehouses. _Source: @tobi ([post](https://x.com/tobi/status/2072368961795039694))_

- **Async UX principle**: Users don't care about async/await mechanics — they care that the app never freezes; the goal is a responsive UI, not the concurrency primitive itself. _Source: @twannl ([post](https://x.com/twannl/status/1979605647311188138))_

## Systems & Infrastructure

- **Software optimizations keep cutting inference cost post-deployment**: In one month on NVIDIA Blackwell, software-only optimizations improved DeepSeek-V4 throughput up to 5×, dropping token cost to ~1/5 — inference cost falls long after hardware ships. _Source: @nvidia ([post](https://x.com/nvidia/status/2071979909199577560))_
- **Selective-precision quantization**: GLM-5.2 (744B MoE) quantized to 4-bit while keeping its MTP draft head in BF16 — matching the FP8 release on quality, fitting on 4×H200 instead of 8, and gaining +69–79% throughput at batch-1 from MTP speculative decoding. Keeping the speculative-draft component at higher precision is the key trick. _Source: @ClementDelangue ([post](https://x.com/ClementDelangue/status/2071991208977530900))_
- **Quantization for local inference**: Qwen3.6-27B in NVFP4 cuts GPU memory ~2.5× while retaining strong accuracy (86.3 MMLU-Pro), making a 27B model practical on local Blackwell hardware. _Source: @vllm_project ([post](https://x.com/vllm_project/status/2072413378669134306))_
- **Blackwell FP4 via llama.cpp**: Recent builds dispatch GEMMs directly to Blackwell FP4 Tensor Cores, letting consumer/local inference exploit hardware low-precision paths for speed. _Source: @julien_c ([post](https://x.com/julien_c/status/2072083673776574847))_
- **vLLM v0.24.0 release**: 571 commits from 256 contributors — highlights: MiniMax-M3 support (FP8/MXFP4 + AMD tuning), maturing DeepSeek-V4 (FlashInfer sparse index cache, prefill chunk-planning), and Model Runner V2 handling quantized models. _Source: @vllm_project ([post](https://x.com/vllm_project/status/2072159562992619991))_
- **vLLM inference optimizations worth knowing**: DeepSeek-V4 gains a FlashInfer sparse index cache (2–4% TTFT) and prefill chunk-planning (+4%); on NVIDIA SM90, CUTLASS FP8 odd-M via `swap_ab` yields a 180–290% kernel speedup and tuned fused_moe FP8 gives +25% for Qwen3-Next-80B on H100. _Source: @vllm_project ([post](https://x.com/vllm_project/status/2072159565991628834), [post](https://x.com/vllm_project/status/2072159568357134523))_
- **PagedAttention being retired in vLLM**: The vLLM maintainer removed PagedAttention — a signal that the original paged-KV-cache design is being superseded by newer memory-management approaches in high-throughput stacks. _Source: @mgoin_ ([post](https://x.com/mgoin_/status/2072489254089798017))_
- **Memory bandwidth is the LLM decode bottleneck**: Decode speed is bandwidth-bound, so it's worth knowing the actual memory bandwidth each compute device provides when reasoning about decode throughput. _Source: @mlech26l ([post](https://x.com/mlech26l/status/2072384858375295301))_
- **Speculative decoding for OCR models**: An EAGLE-3.1 draft model for the Chandra 2 OCR model delivers ~2× speedup at small batch sizes — spec-decoding pays off for latency-sensitive vision/OCR serving. _Source: @charles_irl ([post](https://x.com/charles_irl/status/2072035799860932705))_
- **GPU hardware event capture via a dedicated SASS instruction**: On NVIDIA GPUs, `PMTRIG` (paired with a `CS2R` read of `SR_GLOBALTIMERLO`) captures per-event data — timestamp, event ID, lane, warp, SM — into a per-SM perfmon ring buffer drained later by the runtime. This is the low-level mechanism behind fine-grained kernel profiling. _Source: @drisspg ([post](https://x.com/drisspg/status/2071810466205372610))_
- **AI agents beating human kernel engineers**: Databricks reached #1 on NVIDIA's SOL-ExecBench (L1 single-op track) using Kernel Design Agents — the winning kernels were produced 100% by AI, an early concrete example of recursive self-improvement in performance engineering. _Source: @Yuchenj_UW ([post](https://x.com/Yuchenj_UW/status/2072496816336290143))_

## Business & Strategy

- **Total task cost — not per-token price — is the metric**: Claude Sonnet 5 costs ~$2.29/task on the Intelligence Index (~2× Sonnet 4.6, more than Opus) driven *entirely* by token usage — ~40% more output tokens, and up to ~183 turns/task at max effort (55 at medium) vs 4.6. ## Science & Research

- **"Build a Reasoning Model (From Scratch)"**: A new 440-page book covering inference scaling, reinforcement learning, and distillation implemented from scratch — a structured path into modern reasoning-model techniques. _Source: @rasbt ([post](https://x.com/rasbt/status/2071945864088535126))_
- **Backprop vs. the brain**: A pointed research view — deep learning is built on backpropagation and the brain is not, so any backprop-reliant method (even "brain-inspired" ones like JEPA/HRM) is argued to be a dead end for *understanding* the brain (distinct from building useful AI). _Source: @gabriberton ([post](https://x.com/gabriberton/status/2072171544894431526))_
- **LLMs as "proof machines" shift the researcher's job**: As LLMs produce correct-but-hard-to-read proofs of frontier results, the bottleneck moves from *finding* proofs to *understanding, verifying, and communicating* them — raising the risk of many badly-written papers that nonetheless contain correct results. _Source: @Aaroth ([post](https://x.com/Aaroth/status/2072311488098836521))_
- **Feynman's positron insight**: In "The Theory of Positrons" (1949), rather than invent a new particle for the Dirac equation's negative-energy solutions, Feynman reinterpreted them as an electron's worldline running *backward* in time — mathematically equivalent to a positron moving forward. - **A stats fact worth keeping**: A Poisson arrival process, conditioned on its n-th point, is equivalent to the order statistics of n−1 i.i.d. uniform random variables — a deceptively simple identity with wide practical use. _Source: @ekzhang1 ([post](https://x.com/ekzhang1/status/2072441098597814441))_
- **Fusion direct energy conversion**: Realta demonstrated direct electricity conversion from a fusion reaction at ~90% efficiency, versus ~33% for conventional heat→steam→turbine setups — bypassing the thermodynamic bottleneck of steam-cycle plants. _Source: @FutureJurvetson ([post](https://x.com/FutureJurvetson/status/2072156865296023780))_
- **Big science data, small hardware**: A single Hugging Face release bundles 80TB of astrophysics data from 30+ surveys, yet is designed so ~4GB of RAM suffices even at Gaia scale — a lesson in streaming/columnar design over "load it all into memory." _Source: @Thom_Wolf ([post](https://x.com/Thom_Wolf/status/2072057144996921398)), @smith42mike ([post](https://x.com/smith42mike/status/2071960665959362965))_

## Key Takeaways

1. **Total task cost — not per-token price — is what to benchmark.** Sonnet 5 costs more than Opus purely because it emits ~40% more tokens and takes up to ~183 turns/task; underpowered models retry and can end up *more* expensive ($18.41 vs $1.12 for the same job); and swapping to efficient open models saved 67–82% (5–7×) on real workloads. Always measure end-to-end cost/latency on your own workload. _Source: @ArtificialAnlys ([post](https://x.com/ArtificialAnlys/status/2072062595482456431)), @thorstenball ([post](https://x.com/thorstenball/status/2072193095827947727)), @togethercompute ([post](https://x.com/togethercompute/status/2072468212911137067))_
2. **Big performance wins increasingly come from software and architecture, not bigger models.** DeepSeek-V4 got up to 5× faster on the same Blackwell hardware in a month, weight-delta sync cuts RL traffic ~100–1000× bit-exact, and pipeline design cut agent web-reading ~49×. _Source: @nvidia ([post](https://x.com/nvidia/status/2071979909199577560)), @ramin_m_h ([post](https://x.com/ramin_m_h/status/2071912978769744178)), @NousResearch ([post](https://x.com/NousResearch/status/2071974594961977727))_
3. **The harness/scaffold is now a first-class lever, sometimes as important as the model** — the Scaffold Effect and meta-agent supervision produce large swings in tokens and success rate from orchestration alone. _Source: @SentientAGI ([post](https://x.com/SentientAGI/status/2071956989434040549)), @chrmanning ([post](https://x.com/chrmanning/status/2072421282860454065))_
4. **Task-specific training and data quality beat raw scale on narrow problems.** A 350M model topped 10×-larger ones on structured output, Bridgewater's expert-labeled fine-tune beat prompting by a lot, and a folding robot got *worse* with more noisy demonstrations. _Source: @liquidai ([post](https://x.com/liquidai/status/2071957538086506762)), @johnschulman2 ([post](https://x.com/johnschulman2/status/2072132258463719658)), @berkeley_ai ([post](https://x.com/berkeley_ai/status/2072112681218421133))_
5. **Verify claims — including your own — under realistic conditions and check the counterfactual.** A reported >40% uv speed-up evaporated on a reliable network, AI-adopter employment growth can mask net displacement via market-share effects, and "excess compute" can signal front-loaded capex rather than durable demand. _Source: @charliermarsh ([post](https://x.com/charliermarsh/status/2072472774099022240)), @erikbryn ([post](https://x.com/erikbryn/status/2072002413234717149)), @patientinvestor ([post](https://x.com/patientinvestor/status/2072311098124964144))_
